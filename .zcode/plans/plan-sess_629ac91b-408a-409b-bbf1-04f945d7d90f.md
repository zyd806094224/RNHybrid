# RNHybrid 安卓模块集成 KMP-IM 入口方案

## 一、目标
在 RNHybrid 安卓端原生新增 IM 功能入口，复用已 maven 引入的 `com.github.zyd806094224:shared:1.0.0`，实现「工作台点击 → 会话列表 → 聊天」的完整链路。**仅涉及安卓原生，iOS 暂不处理。**

## 二、设计决策汇总
| 维度 | 方案 |
|---|---|
| 入口位置 | `HomeFragment` 工作台新增「即时消息」MaterialCardView 卡片 |
| UI 承载 | 新建 `android/lib_im` Library 模块，namespace `com.example.rnandroiddemo.im` |
| 登录态衔接 | 复用 RNHybrid 的 `AuthManager` token，进入 IM 时轻量握手拉 userId |
| 未登录拦截 | 点击入口检查 `AuthManager.isLoggedIn()`，未登录跳 `/auth/login` |
| Adapter 实现 | lib_im 内部用原生 `RecyclerView.Adapter` + DataBinding 自实现，不依赖源工程的 `BaseRecyclerViewAdapter`（RNHybrid 的 lib_framework 没有这个类） |
| userId 缺口方案 | 进入会话页前：`AuthManager.token` → `TokenManager.saveToken` → `Api.getUserInfo()` 拉 userId → `TokenManager.saveUserId` → `ChatUseCase.start(token)` 建 WS |

### 改动 5：新建 `lib_im/.../ImSession.kt`（★ 核心握手逻辑）
```kotlin
object ImSession {
    private var inited = false
    /** 用 RNHybrid 已有 token 初始化 IM 会话（拉 userId + 建 WS）。失败抛异常。 */
    suspend fun ensureInited(token: String) {
        if (inited && TokenManager.getToken() == token) return
        TokenManager.saveToken(token)
        // 拉 userId（KMP getUserInfo）
        val info = Api.getUserInfo()
        if (!info.isFailed() && info.user != null) {
            TokenManager.saveUserId(info.user.userId.toString())
        }
        ChatUseCase().start(token)   // 建立 WebSocket
        inited = true
    }
    fun reset() { inited = false; ChatUseCase().stop() }
}
```

### 改动 6：`app/.../ui/home/HomeFragment.kt`
- 新增「即时消息」卡片点击事件：检查 `AuthManager.isLoggedIn()` → 未登录跳 `/auth/login`；已登录跳 `/im/conversation/activity`
- 点击后先在后台触发 `ImSession.ensureInited(token)`（可在 ImConversationActivity 的 initData 里完成，避免阻塞首页）

### 改动 7：`app/src/main/res/layout/fragment_home.xml`
- 新增一个 MaterialCardView（参考现有卡片样式），标题「即时消息」，副标题「KMP-IM 聊天」

### 改动 8：`lib_im/.../ui/ImConversationActivity.kt`
- `initData()` 中调 `ImSession.ensureInited(AuthManager.getToken())`（挂起，需 lifecycleScope）
- 但 lib_im 不能直接依赖 `app` 的 `AuthManager`（循环依赖）。解法：在 `lib_im` 定义 `ImBridge` 接口，由 `app` 实现并通过 `ImBridge.instance = { AuthManager.getToken() }` 注入，或在 `MyApplication` 初始化时把 token provider 注入 lib_im。
- 采用方案：**lib_im 提供 `ImTokenProvider` 函数变量**（默认空），`MyApplication.onCreate` 中赋值 `{ AuthManager.getToken() }`

### 改动 9：`app/.../MyApplication.kt`
- 新增一行：`ImTokenProvider.get = { AuthManager.getToken() }`

### 改动 10：`app/src/main/AndroidManifest.xml`
- 无需改动（lib_im 的 Activity 用 ARouter 跳转，由 lib_im 自己的 manifest 声明）

### 改动 11：新建 `lib_im/src/main/AndroidManifest.xml`
- 空 manifest + package 声明（Activity 通过 ARouter，无需显式声明也可，但建议显式声明并加 exported=false）

## 五、数据流
```
[HomeFragment 即时消息卡片]
   ↓ AuthManager.isLoggedIn()?
   ├─否→ /auth/login (RNHybrid 现有登录页)
   └─是→ ARouter /im/conversation/activity
            ↓ ImConversationActivity.initData()
            ↓ ImSession.ensureInited(AuthManager.token)
            ↓   TokenManager.saveToken(token)
            ↓   Api.getUserInfo() → TokenManager.saveUserId()
            ↓   ChatUseCase.start(token)  // WebSocket 建连
            ↓ 拉会话列表 ChatUseCase.getConversations()
            ↓ 订阅 ChatUseCase.observeMessages() 实时刷新
   → 点击会话 → /im/chat/activity (带 conversationId/targetId/targetName)
            ↓ 拉历史 ChatUseCase.loadHistory()
            ↓ 订阅实时消息 → 追加到列表
            ↓ 发送 → ChatUseCase.sendMessage(targetId, 1, text)
   → 点击"发起聊天" → /im/userlist/activity
            ↓ ChatUseCase.getChatUsers()
            ↓ 选择用户 → /im/chat/activity (conversationId=0)
```

## 八、不做的事
- 不动 iOS / Harmony
- 不改 KMP shared 源码（纯消费 maven 包）
- 不改 RNHybrid 现有登录流程（仅在 MyApplication 注入 token provider）
- 不搬源工程的 `ImLoginActivity`（复用 token 方案不需要）

## 九、风险与缓解
| 风险 | 缓解 |
|---|---|
| RNHybrid token 与 IM 后端非同源，getUserInfo 会 401 | ImSession.ensureInited 失败时在会话页 Toast 提示「IM 初始化失败，请重新登录」，不崩溃 |
| KMP TokenManager 是内存态，App 重启后丢失 | 每次进会话页都走 ensureInited，幂等，重启后自动重建 |
| WebSocket 长连接资源占用 | Application 注册前后台监听，退后台调 `ImSession.reset()` 断开（可选增强，首版可不做） |
| lib_im ↔ app 循环依赖 | 用 `ImTokenProvider` 函数变量解耦，app 单向依赖 lib_im |
